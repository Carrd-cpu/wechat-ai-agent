可运行 Demo Python 3.10+ 零第三方依赖 OpenAI 兼容接口 离线可降级

企业微信 AI 客服 Agent

客户在仿微信的客服工作台里发消息，Agent 完成意图识别、Skills 路由、工具调用和回复生成；遇到投诉、法律等高风险问题自动转人工。有 API Key 走大模型，没有 Key 自动降级到离线规则引擎。

本地运行 看看架构

核心能力

不是"更大的聊天框"，而是决策、行动、再生成。

01

Skills 文件化

每个技能是一份 SKILL.md：触发词、可用工具、执行流程、约束。加业务只加目录，不改 Python。

02

工具是唯一事实源

订单状态、工单号、知识库口径只能来自工具返回值，从机制上限制模型自由发挥。

03

双引擎自动降级

有 Key 走 function calling，无 Key 或调用失败切离线规则引擎，两条路径共用同一套工具。

04

人工接管边界

转人工后 AI 完全静默，只记录消息；坐席可随时把会话交还智能体，历史完整保留。

05

越权防护

查询订单时校验客户归属，不会把 A 客户的订单信息返回给 B 客户。

06

可解释轨迹

每次回复都展示决策链路：意图置信度、命中技能、工具入参与返回值、是否降级。

一条消息走完六步

右侧轨迹面板显示的就是这条链路。

STEP 1
安全策略

高风险词直接转人工

STEP 2
意图识别

规则表 + 置信度

STEP 3
Skills 路由

触发词打分取最高

STEP 4
工具调用

查订单 / 知识库 / 工单

STEP 5
生成回复

模型或离线模板

STEP 6
兜底

查不到就转人工，不编

本地运行

不需要安装任何第三方包，克隆后两条命令即可启动。

# 1. 进入项目目录
cd wechat-ai-agent

# 2. 启动（默认打开 http://127.0.0.1:8000）
python server.py

Windows 也可以直接双击 start.bat。不加参数时会自动打开浏览器；只想启动服务用 python server.py --no-browser。

接入真实大模型（可选）

不配置也能完整跑通，配置后切换到 LLM 引擎。

# 在项目根目录新建 .env
LLM_API_KEY=你的 API Key

默认走 DeepSeek 的 OpenAI 兼容接口，模型和地址可在 config.json 的 llm 段修改。

说明：这个仓库是本地可运行的演示项目，没有部署在线实例。所有客户、订单、知识库数据均为虚构，仅用于展示 Agent 链路。

内置技能与工具

技能由 skills/ 下的 SKILL.md 定义，工具在 agent.py 的 ToolBox 中实现。

类型名称作用
Skillorder-query订单进度、交付时间、物流查询；支持省略式追问补全
Skillafter-sales售后问题受理、创建工单并给出 SLA
Skillproduct-consult产品与价格咨询，只按知识库口径回答
Skillhuman-handoff识别转人工意图，带上下文交给坐席
Toolquery_order按单号或客户查询订单，校验归属
Toolsearch_knowledge关键词加权 + 字符二元组重合度检索
Toolcreate_ticket创建售后工单，返回优先级与 SLA
Tooltransfer_human将会话切换为人工接管状态

几个设计取舍

为什么意图识别先用规则？

高频意图规则命中快、成本为零、可解释；置信度低于阈值的再交给模型分类，避免语义误判和额外调用。

为什么不用 Agent 框架？

链路只有六步，自研三百多行就能完全掌控；每一步都能在轨迹里看到，排查问题比藏在框架内部容易得多。

怎么避免答错？

工具和知识库没有命中就明确说不知道，并转人工；离线引擎只能拼模板，高风险问题直接短路，不进入生成环节。

并发与持久化

会话与工单落 JSON 文件，服务端用锁串行化写入；异常统一返回 JSON，前端有超时与失败兜底，不会无限转圈。
